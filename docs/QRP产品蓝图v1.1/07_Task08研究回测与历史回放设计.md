> **一句话定义**
>
> Task08 不是“建立新的回测系统”，而是在 QRP 已有 Factor Research、Portfolio Backtest、PIT、Strategy Runner、Results 等能力之上，增加一个统一的 back() 编排入口，使因子、局部规则实验、完整策略都能以同一心智模型获得可复现的历史结果。

# 0. 设计决策摘要

本设计冻结 Task08 的核心边界：QRP 的问题已经不是“缺少回测底层能力”，而是这些能力没有被组织成研究者每天会真正使用的工具。Task08 因此只新增薄编排层，不复制已有 engine、PIT、execution、metrics 或 strategy runtime。

> **最终用户心智模型**
>
> 研究者只需要理解三个动作：描述被研究对象 → back() 运行 → 读取结果。底层即使涉及十几个模块，也不向研究接口泄漏。

**概念 API（factor / experiment / strategy 必须且只能三选一）**

```text
back(period, universe=None, *,

factor=None,

experiment=None,

strategy=None,

execution=None,

output=None)
```

| **模式**   | **研究问题**                             | **被研究对象**                        | **主要底层路径**                                                                               |
|------------|------------------------------------------|---------------------------------------|------------------------------------------------------------------------------------------------|
| Factor     | “这个指标/score 有没有信息量？”          | factor / score                        | PIT panel → existing research pipeline → IC / quantile / forward return                        |
| Experiment | “把几条局部规则这样组合，交易表现怎样？” | 临时 score/filter/rank/portfolio/exit | PIT features → experiment evaluator → target weights → PortfolioEngine                         |
| Strategy   | “完整正式策略在过去会做什么、表现怎样？” | formal strategy code + params         | historical input assembly → formal strategy runner → StrategyPortfolioTarget → PortfolioEngine |

- Factor 与 Experiment 允许 intentionally partial：只研究写出来的东西；普通未写规则不自动继承 System B。

- Formal Strategy 保持封装：其 indicator/filter/rank/entry/exit/state/portfolio 仍属于策略内部，不从 back() 外部拆散传入。

- Production Contract 保持 strict / fail-closed；研究的省略或假设不能反向污染生产策略语义。

- Task08 是一个任务；本文的“实施步骤”只是单任务内部落地顺序，不拆成 Task08-A/B/C/D。

# 1. 背景与问题定义

## 1.1 原路线图中的 Task08

v1.1 路线图原先把 Task08 定义为“历史回放（只读）+ Dry-Run（试跑）”：历史回放要求 PIT、可复现、可审计；Dry-Run 要模拟完整日切但不落生产。这个方向本身没有错，但若把所有内容同时作为第一次 research 的前置条件，会继续推迟真正使用回测系统。

本设计对路线图做的是“交付顺序收缩”，不是否定原目标：先让历史研究 / 回放入口真正可用；Dry-Run、完整日切、更多产品化能力不再作为 Task08 首次可用性的阻塞条件。

## 1.2 代码调研后的真实现状

QRP 已经存在多层回测基础设施：Factor Research、PIT primitives、PortfolioEngine、A 股执行约束、Strategy → PortfolioEngine bridge、结果分析与产品层。换言之，重活大部分已经存在；缺口集中在“如何从一个研究问题快速到达这些底层能力”。

| **现有能力**         | **主要位置**                                | **Task08 处理方式**                                                   |
|----------------------|---------------------------------------------|-----------------------------------------------------------------------|
| Factor / score 研究  | backtest/research/pipeline.py               | 直接复用；Factor mode 只做输入/输出适配                               |
| PIT as-of primitives | backtest/point_in_time.py, pit_queries.py   | 直接复用；Task08 不重造 PIT 引擎                                      |
| 组合回测             | backtest/portfolio/engine.py                | 直接复用；Experiment / Strategy 统一进入该层                          |
| 交易与约束配置       | backtest/portfolio/models.py, execution.py  | 直接复用 PortfolioBacktestConfig / execution behavior                 |
| 正式策略桥接         | backtest/portfolio/strategy.py              | Strategy mode 的主路径；原生 StrategyPortfolioTarget 可转换为 weights |
| 兼容 runtime         | backtest/runtime/strategy.py                | 仅保留其历史兼容用途；当前 develop 对 native PortfolioTarget 明确拒绝 |
| 结果 / metrics       | backtest/results/\*, metrics.py             | 直接复用并统一包装为 BackResult                                       |
| product/service/API  | backtest/product/\*, api/routes/backtest.py | Task08 首版不强制接入，除非复用能显著减少工作量                       |

> **关键纠偏**
>
> 完整 System B Strategy Replay 不应接到 backtest/runtime/strategy.py 的 vectorized compatibility runtime。当前 develop/v1.1 中该 runtime 遇到原生 StrategyPortfolioTarget 会直接报错；应复用 backtest/portfolio/strategy.py 的正式 portfolio bridge。

# 2. 目标、非目标与成功标准

## 2.1 目标

- 形成一个统一、低摩擦的 back() 研究 / 回放入口。

- 允许研究 1–3 个已有指标、一个 score、一个过滤条件、一个 ranking 或一条 ENTRY/EXIT 假设，而不要求完整 System B。

- 允许完整 formal strategy 原样封装后进行历史回放 / 组合模拟。

- 所有路径尽可能复用现有 PIT、ResearchPipeline、PortfolioEngine、execution、metrics 和 results。

- 保存足够的 config / version / provenance，使同一研究可解释、可比较、可复跑。

- 第一次真实研究必须在 Task08 内完成，而不是把“能跑研究”继续推迟到后续任务。

## 2.2 非目标（明确禁止 scope creep）

- 不建立新的 Backtest Engine。

- 不设计万能 DSL、规则图、AST、插件注册表、Provider Factory。

- 不为了 Research 修改或放宽生产 System B 的 fail-closed Contract。

- 不要求先完成所有 System B upstream producer / state / episode 历史重放，才允许做局部研究。

- 不强制建设 GUI、异步任务平台、分布式批量回测。

- 不要求 Task08 首版完成完整 Dry-Run 日切产品化。

- 不以“把旧 backtest 全部统一重构”为交付目标。

> **Task08 的硬 Scope Rule**
>
> 凡是不能直接帮助“今天拿一个指标 / 规则 / strategy 跑出可信历史结果”的内容，一律不作为 Task08 的阻塞项。

# 3. 统一入口设计

## 3.1 外部 API：一个 back()，三个 subject

```text
def back(

period,

universe=None,

*,

factor=None,

experiment=None,

strategy=None,

execution=None,

output=None,

) -> BackResult:

...
```

约束：factor / experiment / strategy 必须且只能提供一个。period 必填；universe 对 Factor / Experiment 必填，对 Strategy 可由策略或历史输入组装器提供，若外部也传入必须做显式兼容性校验，不允许静默覆盖策略自己的 universe 语义。

对外 API 可以是 Python、YAML CLI 或后续 API 的不同表面；内部都必须先归一化为同一个 BackRequest。

**内部规范化模型**

```text
BackRequest

period

universe?

subject: FactorSubject | ExperimentSubject | StrategySubject

execution?

output?
```

## 3.2 Factor mode：验证信息价值

Factor mode 回答“这个指标 / score 是否对未来收益存在稳定的排序或预测信息”。它不要求构造持仓，也不必进入 PortfolioEngine。

```text
back(

period=("2023-01-01", "2026-06-30"),

universe="system_b_universe",

factor={

"field": "m1_rank",

"direction": "lower_is_better",

"horizons": [5, 20],

"quantiles": 5,

},

)
```

最小输出：coverage、IC / Rank IC、quantile returns、long-short、forward-return diagnostics；turnover / cost sensitivity 等已有能力按配置启用，不要求用户每次手工声明底层细节。

## 3.3 Experiment mode：验证局部规则组合

Experiment mode 是 Task08 对“研究迟迟不能开始”最直接的解决方案。它把一组临时研究规则翻译为 target weights，再交给现有 PortfolioEngine。它不是一个正式 Strategy，也不继承完整 System B。

| **自然语言问题**      | **Experiment 最小概念** |
|-----------------------|-------------------------|
| 看什么？              | indicator / score       |
| 谁能参加？            | filter                  |
| 怎么排？              | rank                    |
| 选多少、持多少？      | portfolio               |
| 什么时候离开 / 更新？ | exit / rebalance        |

```text
back(

period=("2023-01-01", "2026-06-30"),

universe="system_b_universe",

experiment={

"score": "0.5 * m1_rank + 0.5 * m2_rank",

"filter": "is_positive_profit == true",

"rank": {"by": "score", "order": "asc"},

"portfolio": {"top_n": 6, "weight_each": 0.125},

"exit": "when_not_selected",

},

execution={"preset": "a_share_daily"},

)
```

> **省略语义**
>
> 普通研究规则“没写”就表示“不属于这个实验”，而不是要求声明 enable_xxx=false。只有当实验主动替代了生产中本应强制存在的 safety/gating 依赖时，才必须把该替代写入 research_assumptions，以便审计。

**仅在确实替代生产依赖时显式记录**

```text
experiment={

"score": "m1_rank",

"portfolio": {"top_n": 6, "weight_each": 0.125},

"research_assumptions": {

"authorization": "assumed_authorized_for_experiment"

}

}
```

## 3.4 Strategy mode：完整正式策略回放

Strategy mode 与 Experiment 的最大区别是：完整 Strategy 自己拥有其业务规则。back() 只负责历史环境、输入组装、调用正式 runner、组合模拟和结果收集；不从外部重新声明内部 indicator / filter / rank / entry / exit / state。

```text
back(

period=("2023-01-01", "2026-06-30"),

strategy={

"code": "system_b_portfolio",

"params": {...},

},

execution={"preset": "a_share_daily"},

)
```

Strategy mode 的核心约束：若历史输入缺少 formal strategy 要求的 comparison_score、entry_eligible、exit trigger、severe abnormal status、authorization 或其他事实，runner 必须明确失败并报告缺口；不得自动用 Research 的“省略规则”语义替代生产依赖。

# 4. 三种模式的边界与汇合点

## 4.1 Factor 不强行进入组合回测

```text
PIT historical panel

↓

factor / score

↓

existing ResearchPipeline

↓

IC / quantile / forward-return diagnostics

↓

BackResult.factor
```

Factor 研究的目标是判断“有没有信息价值”，不是证明一套交易系统，因此不为了统一形式而强制制造 target 或 order。

## 4.2 Experiment 与 Strategy 在 Portfolio Target / target weights 汇合

```text
┌─ Experiment rules ──→ ExperimentEvaluator ──┐

historical PIT inputs ────┤ ├─→ target weights

└─ Formal Strategy ─→ StrategyPortfolioTarget ─┘

↓

PortfolioBacktestEngine

↓

execution / NAV / trades / metrics
```

这使底半段可以完全复用。Experiment 的价值只是产生 target；正式 Strategy 的价值是产生正式 StrategyPortfolioTarget。两者不需要共享同一种规则描述语言。

> **最重要的封装原则**
>
> 不要为了让 back() 看起来“统一”，把完整 System B 拆回 indicator/filter/rank/exit 参数。统一的是“被研究对象的入口”和“结果”，不是统一策略内部实现。

# 5. 现有能力复用与新增边界

## 5.1 直接复用，不重写

| **层**          | **复用对象**                                                   | **Task08 职责**                                        |
|-----------------|----------------------------------------------------------------|--------------------------------------------------------|
| PIT / data      | PointInTimeFactTableSpec、as-of filter、historical loaders     | 选取 / 组装所需历史输入；不重造版本选择逻辑            |
| Factor research | run_research_pipeline()                                        | 构造 ResearchConfig / panel，并把结果适配为 BackResult |
| Portfolio       | PortfolioBacktestEngine / PortfolioBacktestConfig              | 把 experiment / strategy 输出 target 接进去            |
| Execution       | 现有 A 股 daily execution constraints                          | 通过 preset / config 复用，不让研究者每次声明所有细节  |
| Strategy        | run_strategy_portfolio_backtest() / portfolio strategy adapter | Formal Strategy path 的唯一推荐 bridge                 |
| Results         | 现有 analytics / trades / orders / risk                        | 统一汇总 / artifact 索引                               |

## 5.2 Task08 最小新增组件

建议新代码保持一个小型 harness package；不要预先拆出大量 Adapter/Factory。文件可以在实现中按现有项目风格微调，但职责必须保持以下三块：

```text
src/qrp_atlas/backtest/harness/

models.py # BackRequest / BackResult / FactorSpec / ExperimentSpec / StrategySpec

runner.py # back() + validation + simple dispatch

experiment.py # partial-rule evaluator → target weights



tests/backtest/harness/

...
```

- Factor adapter：尽量只是 runner.py 中的一个小函数，只有复杂度真实增长后再拆文件。

- Strategy adapter：直接围绕 backtest/portfolio/strategy.py，避免另造 Strategy runtime。

- CLI：若仓库已有统一 CLI 机制，则加一个薄 wrapper；命令名服从现有 CLI 规范，不因 Task08 另建命令框架。

- Artifact：优先复用现有 result/product persistence；若接入代价过高，只保存最小本地 artifact，不为产品层重构阻塞研究。

# 6. BackResult 与可复现性

## 6.1 统一结果不是“所有模式强制同字段”

BackResult 是统一容器，不是把 Factor 和 Portfolio 强行压成同一种数据。公共 metadata 一致，模式专属结果按需存在。

```text
BackResult

status

run_id

subject_type: factor | experiment | strategy

request_snapshot

provenance

summary_metrics

factor?

ic / rank_ic / quantile_returns / forward_returns / turnover ...

portfolio?

equity / drawdown / positions / trades / orders / risk_events ...

replay?

target_snapshots / decision_trace ...

warnings

artifacts
```

## 6.2 最小 provenance

- canonical BackRequest（排序稳定的 JSON/YAML）与 config hash；

- period / universe / subject；

- QRP git SHA / strategy code version；

- PIT input version / source_version / ingested_at 选择信息（按现有能力可得程度记录）；

- PortfolioBacktestConfig / execution preset 的实际展开值；

- warnings / missing-data diagnostics / assumptions；

设计目标是：同一 request + 同一 code/version + 同一历史输入版本，应得到相同结果。Task08 首版不必为此建立新的全局 lineage 平台，但不能只保存一张收益曲线而丢掉实验定义。

# 7. Historical Replay、PIT 与 Backtest 的关系

| **概念**             | **核心问题**                                     | **Task08 输出**                                            |
|----------------------|--------------------------------------------------|------------------------------------------------------------|
| Replay correctness   | “站在 D 日，只看当时可见数据，系统会输出什么？”  | as-of input provenance、decision/target snapshot、warnings |
| Performance backtest | “这些 target 在执行假设下会形成什么持仓与 P&L？” | orders / trades / positions / NAV / drawdown / metrics     |

两者必须区分，但可以在同一次 Strategy / Experiment run 中串联：先生成当日 target，再交给 PortfolioEngine。这样 Task08 既保留路线图的“历史回放”本义，也满足今天最急需的“研究反馈”。

> **PIT 边界**
>
> 现有 point_in_time.py 证明 QRP 已有 as-of primitives，但这不等于所有 System B 当前 facts / state / episode producer 已天然可在历史上重放。Task08 不得虚构这一能力；Strategy mode 遇到尚未可历史组装的正式输入时，应把缺口暴露出来。

# 8. 输入验证与失败语义

| **场景**               | **要求**                                                                            |
|------------------------|-------------------------------------------------------------------------------------|
| subject 冲突           | factor / experiment / strategy 非三选一 → 立即拒绝                                  |
| 未知字段 / 表达式      | fail fast；不猜字段名、不自动降级                                                   |
| Experiment 非法 target | 权重非有限值、超约束、选择结果不合法 → 明确失败或交现有 invalid-target policy       |
| Strategy 缺正式 facts  | fail closed；输出 missing facts / provenance，不套用 Experiment 的省略语义          |
| PIT future leakage     | strict mode 下拒绝；必须有诊断信息                                                  |
| Research assumption    | 只允许 Experiment mode 使用；必须进入 request snapshot 与 artifacts                 |
| 生产副作用             | Task08 全部历史运行只读；不得更新 canonical facts / state / episode / authorization |

# 9. Execution 配置：默认复杂性藏在 preset 后

QRP 的 PortfolioBacktestConfig 已包含佣金、滑点、印花税、lot size、单票上限、持仓数、换手限制、T+1、涨跌停、停牌等大量现实约束。Research 接口不应要求每次重新声明。

```text
execution:

preset: a_share_daily
```

preset 展开为现有 PortfolioBacktestConfig。研究者只有在研究执行假设本身时才覆盖具体参数，例如 commission、slippage 或 rebalance。实际展开后的 config 必须写入 BackResult provenance。

# 10. 单一 Task08 的实施顺序

以下是一个 Task08 内部的实现顺序，不建立 Task08-A / B / C / D 子路线。每一步都围绕“让第一次真实 research 跑起来”服务。

| **顺序**                          | **实施内容**                                                                                                                                       |
|-----------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| 1\. 冻结 BackRequest / BackResult | 先把三选一 subject、period/universe、execution、provenance 的边界写成最小模型与 validation。                                                       |
| 2\. 接 Factor path                | 用一个真实已有 indicator 跑通 PIT panel → run_research_pipeline() → BackResult.factor；不新增 factor engine。                                      |
| 3\. 接 Experiment path            | 实现极小 ExperimentEvaluator，只支持当前真实研究需要的 score/filter/rank/top_n/weight/exit/rebalance；生成 target weights 后调用 PortfolioEngine。 |
| 4\. 接 Strategy path              | 复用 backtest/portfolio/strategy.py 正式 bridge；禁止把 native StrategyPortfolioTarget 送进 runtime/strategy.py compatibility path。               |
| 5\. 结果与 artifact               | 保存 request snapshot、versions、metrics、equity/trades/diagnostics；优先复用现有 results 能力。                                                   |
| 6\. 薄 CLI / callable             | 提供一个真正可被每天使用的入口；命令层不加入额外业务逻辑。                                                                                         |
| 7\. 第一次真实研究验收            | 修改一个指标 / threshold / weight 后立即 rerun，对比两次可复现结果。                                                                               |

# 11. 首次真实使用场景

## 11.1 Factor smoke：M1 单因子

目的不是证明 System B，而是证明“QRP 的一个现成指标可以今天就被研究”。要求至少输出 5D / 20D forward-return 的 IC / Rank IC / quantile diagnostics。

## 11.2 Experiment smoke：score → Top-N portfolio

使用一个真实可获得的 score（如 M1 或 composite 的当前可用形式），限定 universe，选择 Top 6，每只 12.5%，经现有 PortfolioEngine 得到 equity / max drawdown / trades / turnover / holdings。然后只改一个参数，例如 Top 6 → Top 10，重新运行并比较。

## 11.3 Strategy smoke：system_b_portfolio

Task07-C 合并后，验证 formal strategy 输出的 StrategyPortfolioTarget 能通过 backtest/portfolio/strategy.py 进入 PortfolioEngine。若当前历史事实组装不足以满足 strategy contract，这个测试可以以“准确报告缺失输入”为通过，不允许伪造事实以制造绿色结果。

# 12. 测试矩阵

| **类别**        | **核心测试**                                                                                     |
|-----------------|--------------------------------------------------------------------------------------------------|
| Contract        | factor/experiment/strategy exactly-one；period/universe validation；unknown field fail-fast      |
| Factor          | 同一 panel/config 得到稳定 ResearchResult；BackResult mapping 正确                               |
| Experiment      | filter/rank/top_n/weight/exit 的最小语义；target 生成稳定；非法 target 不静默修复                |
| Strategy        | formal runner 被调用；native StrategyPortfolioTarget 进入 portfolio bridge；缺 facts fail-closed |
| PIT             | as-of D 不读取 available_at\>D / ingested_at 未来修订；strict diagnostics 可见                   |
| Execution       | preset 被正确展开并进入 PortfolioBacktestConfig；T+1/lot/fees 等继续由原 engine 负责             |
| No side effects | 历史运行不写 canonical facts，不推进 state/episode，不创建 trade authorization                   |
| Reproducibility | 相同 request + versions 输出 config hash / 关键结果稳定；artifact 完整                           |
| Isolation       | Experiment research_assumptions 不进入 Strategy mode / production contract                       |

# 13. Definition of Done

Task08 完成时必须同时满足：

- 存在一个统一 back() / 等价 CLI 入口，Factor / Experiment / Strategy 三种 subject 可被明确选择。

- Factor mode 使用真实历史数据跑出一份可信结果。

- Experiment mode 能在不修改 engine 代码的前提下，修改一个 score / filter / rank / weight / exit 参数并重新运行。

- Experiment / Strategy 两条 portfolio 路径复用现有 PortfolioEngine 与 execution 约束。

- Strategy mode 使用 backtest/portfolio/strategy.py 的正式 StrategyPortfolioTarget bridge；不走不兼容的 vectorized runtime。

- 所有历史运行只读，无生产 side effects。

- 每个 run 留下 request snapshot、版本/provenance、metrics 与必要 artifacts。

- 至少完成一次“两个配置只差一个参数”的真实对比研究，证明 QRP 已从“有回测底层”变成“可日常使用的研究工具”。

> **不属于 DoD**
>
> GUI、完整 Dry-Run、万能 Rule DSL、批量参数搜索平台、所有 System B producer 的历史化、产品 API 重构，均不作为 Task08 完成条件。

# 14. 设计决策记录（冻结项）

| **ID** | **冻结决策**                                    | **理由**                                                  |
|--------|-------------------------------------------------|-----------------------------------------------------------|
| D01    | 一个 back()，三种互斥 subject                   | 统一心智，不强行统一内部算法                              |
| D02    | Factor 不必进入 PortfolioEngine                 | 因子价值与交易组合是不同问题                              |
| D03    | Experiment 只表达当前实验规则                   | 允许 partial research，避免完整 System B 成为前置条件     |
| D04    | Formal Strategy 保持封装                        | 不在 back() 外重复策略内部规则                            |
| D05    | Experiment / Strategy 在 target 层汇合          | 最大化复用 PortfolioEngine / execution                    |
| D06    | Research omission ≠ Production fallback         | 保护生产 fail-closed 语义                                 |
| D07    | 不新建回测 engine / DSL / registry              | QRP 已有底座，Task08 的价值是编排而非重构                 |
| D08    | Dry-Run 不阻塞首次 research                     | 先形成真实反馈闭环，再由实际缺口决定后续建设              |
| D09    | Strategy native target 走 portfolio/strategy.py | 当前 vectorized runtime 明确不支持 native PortfolioTarget |
| D10    | 真实研究是 Task08 验收的一部分                  | 避免再出现“平台功能完成但从未真正使用”的状态              |

# 15. 已知限制与实现时必须实锤的问题

以下问题是真实集成风险，但不是提前扩建平台的理由。实现 Agent 必须先通过代码 / 数据验证，再决定最小补丁：

- 当前各研究指标 / System B facts 的历史存储形式、PIT 字段完整度及 universe 可重建程度。

- ExperimentEvaluator 最低需要支持哪些表达式；首版只实现第一个真实研究场景所需语义，禁止先做通用规则语言。

- 现有 results/product persistence 是否足以直接保存 BackResult；若接入成本大，先用最小 artifact。

- Task07-C 合并后的 system_b_portfolio 正式注册点、historical StrategyInput 组装路径及所缺 facts。

- 原路线图“回放 3–5 年”的数据覆盖是否对首个 factor/experiment 都现实可用；覆盖不足应报告，不为凑年限制造未来泄漏或伪数据。

> **处理原则**
>
> 遇到缺口时，优先补“连接所需的最小 adapter / input assembly”；只有证据证明现有底层能力确实缺失，才新增底层能力。

# 16. 实现约束（给开发 Agent）

1.  先审计现有接口和测试，确认复用点；不要先创建新 framework。

2.  先跑通一个真实 Factor case，再实现 Experiment；每增加一层都必须有实际使用场景。

3.  Experiment 的规则表达只实现已冻结用例，禁止提前抽象 AST / registry / plugin system。

4.  Strategy mode 直接复用 formal strategy→portfolio bridge；任何 compatibility path 都必须有测试证明可用。

5.  所有历史数据读取遵循 PIT / as-of 语义；任何证据不足必须以明确错误或 diagnostics 暴露。

6.  不修改 production System B contract 来迁就 research。

7.  完成后用一组真实历史数据演示：原配置 → 改一个参数 → rerun → 对比结果。
