> **一句话定义**
>
> Task08 不建立新的回测系统，而是在 QRP 已有 Factor Research、PIT、PortfolioEngine、Execution、Strategy 与 Results 能力之上增加一个薄的 `back()` Harness，使 Factor、局部 Experiment 与完整 Strategy 都能低摩擦得到可复现历史结果。

## 0. 设计结论

QRP 当前主要缺口不是回测底层，而是缺少把研究问题连接到底层能力的统一入口。因此 Task08 的核心对象只有：

```text
Subject → back() → BackResult
```

`Subject` 必须且只能三选一：

- `factor`：研究指标/score 是否具有信息价值；
- `experiment`：研究局部 score/filter/rank/portfolio/exit 组合；
- `strategy`：回放完整正式策略。

Design v1.1 已吸收工程审计 required errata：

1. 增加正式内存数据注入通道，单元测试不依赖生产 DuckDB；
2. System B Strategy 改为按交易日时序驱动，不再错误地假设可一次性运行多日 panel；
3. Factor smoke 不再绑定 `m1_rank`，优先使用当前已有完整历史字段；
4. `universe` 改为有限命名或显式 ticker 列表，取消悬空的 `system_b_universe`；
5. 冻结 Experiment score/filter 的安全表达边界，禁止 `eval()` 与万能 DSL；
6. 冻结 execution preset、subject 语义与显式 override 的覆盖/冲突规则；
7. 明确首版 System B Replay 的状态反馈边界：`decision/target replay → execution simulation`，不宣称 execution-aware fully closed-loop。

---

## 1. 目标与非目标

### 1.1 目标

- 提供统一、低摩擦的 `back()` 研究/回放入口；
- 支持 1–3 个指标、一个 score、过滤、ranking、Top-N、weight、exit/rebalance 的局部实验；
- 支持完整 formal strategy 保持封装后进行历史回放；
- 复用现有 PIT、ResearchPipeline、PortfolioEngine、execution、metrics/results；
- 保存 config、版本、数据来源、universe 解析、execution 展开值与 diagnostics；
- Task08 内必须完成第一次真实研究，而不是继续把“真正开始 research”推迟到后续任务。

### 1.2 非目标

Task08 首版明确不做：

- 新 Backtest Engine；
- 万能 Rule DSL / AST / Python expression parser；
- Plugin Registry / Provider Factory；
- GUI、分布式批量回测、参数搜索平台；
- 完整 Dry-Run 日切产品化；
- 为 Research 放宽 Production System B fail-closed contract；
- 预先补齐所有 System B producer 的历史化；
- execution result 反向驱动次日策略的 fully closed-loop engine。

> **硬 Scope Rule**：凡是不能直接帮助“今天拿一个指标、规则或 strategy 跑出可信历史结果”的内容，不作为 Task08 阻塞项。

## 2. 统一入口

### 2.1 `back()`

```python
def back(
    period,
    universe=None,
    *,
    factor=None,
    experiment=None,
    strategy=None,
    execution=None,
    output=None,
    data=None,
) -> BackResult:
    ...
```

约束：

- `factor / experiment / strategy` 必须且只能提供一个；
- `period` 必填；
- `universe` 类型：`str | Sequence[str] | None`；
- `data` 类型：`Mapping[str, pd.DataFrame] | None`；
- Python / YAML CLI / 后续 API 都必须先归一化为同一个 `BackRequest`。

### 2.2 `data`：正式内存注入点

`data` 用于本地开发、CI、单元测试、Notebook 以及调用方已经准备好历史 panel 的场景。它不是新的 Data Provider Framework。

首版标准键按模式使用：

- `prices`：组合回测历史行情；
- `factors`：Factor / Experiment 特征 panel；
- `facts`：Formal Strategy 已准备事实；
- `universe_membership`：动态 universe 成员关系。

若 `data is None`，Harness 才调用现有历史 loader / PIT 查询。核心 Harness 自动化测试不得因为本机没有完整生产数据库而无法执行。

### 2.3 Universe 规范

首版正式支持：

1. 显式 `Sequence[str]` ticker 列表；
2. `"all_a"`

保留但暂不启用：

- `"system_b_active_pools"`
  原因：尚无正确的 `trade_date`-level PIT membership resolver；在 resolver 完成前必须 fail-fast，禁止将 period 内成员并集作为静态 universe。

其他字符串全部 fail-fast。原设计中的 `system_b_universe` 取消，因为当前代码没有该标准解析器。指数代码等新语义只有在真实 resolver 存在后再加入。

对 Strategy mode，如果 formal strategy / historical input assembler 已拥有自身 universe 语义，则外部 `universe` 可以省略；若同时提供必须显式校验，不允许静默覆盖。

内部最小模型：

```text
BackRequest
  period
  universe?: str | Sequence[str]
  subject: FactorSubject | ExperimentSubject | StrategySubject
  execution?
  output?
  data?: Mapping[str, DataFrame]
```

## 3. 三种模式

### 3.1 Factor：验证信息价值

问题：**这个指标/score 是否对未来收益具有排序或预测信息？**

Factor 不要求构造 portfolio，也不强制进入 PortfolioEngine。

真实 smoke 优先使用当前已经具备历史覆盖的字段，例如 `daily_basic.turnover_rate`、`pb` 或稳定行情派生的 20 日动量：

```python
back(
    period=("2023-01-01", "2026-06-30"),
    universe="all_a",
    factor={
        "field": "turnover_rate",
        "direction": "higher_is_better",
        "horizons": [5, 20],
        "quantiles": 5,
    },
)
```

本地/CI 可直接：

```python
back(
    period=("2025-01-01", "2025-03-31"),
    universe=["000001.SZ", "000002.SZ"],
    factor={"field": "factor_x", "horizons": [5, 20]},
    data={"prices": price_df, "factors": factor_df},
)
```

最小输出：coverage、IC、Rank IC、quantile returns、long-short、forward-return diagnostics。

`m1_rank / m1_score` 只有在历史数据实际存在时才作为额外真实案例或 synthetic smoke，**不属于 Task08 DoD 硬依赖**。

### 3.2 Experiment：验证局部规则组合

Experiment 是 intentionally partial 的研究对象，不是完整 System B，也不会自动继承未写出的生产规则。

最小概念：

| 问题 | 字段 |
|---|---|
| 看什么 | score |
| 谁能参加 | filter |
| 怎么排 | rank |
| 选多少/持多少 | portfolio |
| 什么时候更新/离开 | exit / rebalance |

首版表达边界冻结为：

- `score`：
  - 单字段字符串，例如 `"momentum_20d"`；
  - 或线性权重映射，例如 `{"momentum_20d": 0.5, "turnover_rate": 0.5}`；
- `filter`：
  - 单布尔列字符串；
  - 或结构化白名单谓词：`field / op / value`；
  - 允许的 `op`：`eq / ne / gt / ge / lt / le / in / not_in`；
- 禁止 Python 原生 `eval()`；
- 禁止为了任意公式建立 AST/DSL/parser；
- 未知字段/运算符 fail-fast。

示例：

```python
back(
    period=("2023-01-01", "2026-06-30"),
    universe="all_a",
    experiment={
        "score": {"momentum_20d": 0.5, "turnover_rate": 0.5},
        "filter": {"field": "pb", "op": "gt", "value": 0},
        "rank": {"by": "score", "order": "desc"},
        "portfolio": {"top_n": 6, "weight_each": 0.125},
        "exit": "when_not_selected",
    },
    execution={"preset": "a_share_daily"},
)
```

普通规则“没写”就表示“不属于这个实验”，无需堆 `enable_xxx=false`。只有主动替代生产 safety/gating 依赖时，才写入 `research_assumptions`，并进入 provenance。

### 3.3 Strategy：完整正式策略回放

完整 Strategy 自己拥有 indicator/filter/rank/entry/exit/state/portfolio 业务规则；`back()` 不从外部拆散重新声明。

```python
back(
    period=("2023-01-01", "2026-06-30"),
    strategy={"code": "system_b_portfolio", "params": {...}},
    execution={"preset": "a_share_daily"},
)
```

#### 3.3.1 两类 Strategy runner

不能假设所有 formal strategy 都可以一次性吃完整历史 panel：

- **可向量化/多日策略**：只有已有测试证明支持整段历史输入时，才允许复用 `run_strategy_portfolio_backtest()`；
- **单日 stateful strategy**：Harness 按交易日 step。当前 `system_b_portfolio` 属于此类。

System B 每个交易日 D 的 driver 必须：

1. 读取 as-of D 的 facts / candidate domain / authorization / score provenance；
2. 组装仅包含 D 日的 `StrategyInput`；
3. 带入上一日 strategy holding state；
4. 调用正式 `run_strategy_checked()`；
5. 得到当日 `StrategyPortfolioTarget`；
6. 复用 `strategy_result_to_target_weights()` 转为当日 weights；
7. 更新下一交易日需要的 strategy state；
8. 汇总完整 target-weight 序列后交给 `PortfolioBacktestEngine`。

**禁止**把多日 System B facts 一次性送入 `run_strategy_portfolio_backtest()`。

#### 3.3.2 首版状态反馈边界

当前 `PortfolioBacktestEngine.run()` 是整段批处理接口。Task08 首版冻结为：

```text
day-by-day formal decision/target replay
                 ↓
complete target-weight series
                 ↓
PortfolioBacktestEngine execution simulation
```

因此首版不得声称已经实现“实际 fills / rejected orders / drift 反向改变次日 System B 决策”的 execution-aware fully closed-loop replay。

如果真实研究后证明这一能力必要，再单独评估 PortfolioEngine step/session；不提前扩建。

Strategy 缺 `comparison_score`、`entry_eligible`、exit trigger、severe abnormal、authorization/provenance 等正式输入时必须 fail-closed，并准确报告缺口；不得借用 Experiment 的省略语义。

## 4. 汇合点

Factor 单独走 ResearchPipeline：

```text
historical/PIT panel → factor → ResearchPipeline → diagnostics
```

Experiment 与 Strategy 在 target 层汇合：

```text
Experiment rules → ExperimentEvaluator → target weights ─┐
                                                          ├→ PortfolioBacktestEngine
Formal Strategy → StrategyPortfolioTarget → weights ─────┘
```

统一的是入口与结果，不是把 formal strategy 拆回一个通用规则语言。

## 5. 复用与最小新增代码

### 5.1 直接复用

| 层 | 复用对象 | Task08 责任 |
|---|---|---|
| PIT/Data | `point_in_time.py`、现有 historical loaders | 数据装配；支持 `data` 直通 |
| Factor | `run_research_pipeline()` | 输入/结果适配 |
| Portfolio | `PortfolioBacktestEngine` / `PortfolioBacktestConfig` | 执行完整 target 序列 |
| Execution | 现有 A 股 daily constraints | preset/config 复用 |
| Strategy runner | `run_strategy_checked()` | 正式策略调用 |
| Target conversion | `strategy_result_to_target_weights()` | native target → weights |
| Results | analytics / trades / orders / risk | BackResult 汇总 |

`run_strategy_portfolio_backtest()` 仍可服务已有证明可向量化的策略，但不是所有 Strategy mode 的统一 bridge。

### 5.2 最小新增组件

建议：

```text
src/qrp_atlas/backtest/harness/
  models.py       # BackRequest / BackResult / subject specs
  runner.py       # back() / validation / data + universe resolution / dispatch
  experiment.py   # partial rules → target weights

tests/backtest/harness/
```

原则：

- 不新建 Data Provider Framework；
- Factor adapter 能留在 `runner.py` 就不拆；
- System B day-by-day driver 可以是极薄 helper，但不得复制 System B 业务规则；
- CLI 只是 wrapper；
- Artifact 优先复用现有 results/product，接入过重时先保留最小本地 artifact。

## 6. Execution 配置与优先级

`preset: a_share_daily` 隐藏佣金、滑点、印花税、lot size、T+1、涨跌停、停牌等默认复杂性。

覆盖规则：

1. `preset` 提供默认值；
2. subject 自身语义高于 preset 默认，例如 Experiment 的 `top_n=6 / weight_each=0.125`；
3. 用户显式 execution override 可以覆盖 preset；
4. 显式 override 若与 subject 必要语义冲突，**fail-fast**，不得静默缩容/缩权；
5. 最终 `PortfolioBacktestConfig` 以及关键字段来源（preset / subject / explicit override）全部进入 provenance。

例如：Experiment 明确 Top 6，而 preset 默认 max_positions=5，可由 subject 修正默认值；若用户又显式写 `execution.max_positions=5`，则配置自相矛盾，直接拒绝。

## 7. BackResult 与可复现性

统一容器不意味着 Factor 与 Portfolio 强制拥有同一字段：

```text
BackResult
  status / run_id / subject_type
  request_snapshot
  provenance
  summary_metrics
  factor?     # IC / rank IC / quantile / forward returns
  portfolio?  # equity / drawdown / positions / trades / orders / risk
  replay?     # decision / target snapshots
  warnings
  artifacts
```

最小 provenance：

- canonical BackRequest + config hash；
- period / resolved universe；
- data 来源：in-memory injection 或 loader/PIT；
- QRP git SHA / strategy version；
- PIT/source/ingestion version（可得时）；
- resolved PortfolioBacktestConfig + 字段来源；
- assumptions / warnings / missing-data diagnostics；
- Strategy Replay 的 state-feedback limitation。

相同 request + code/version + historical input version 应得到相同结果。

---

## 8. Replay 与 Backtest 的区别

| 概念 | 问题 |
|---|---|
| Replay correctness | 站在 D 日，只看当时可见数据，策略输出什么？ |
| Performance backtest | 这些 target 在执行假设下形成什么持仓与 P&L？ |

二者可以串联，但不能混为一个概念。PIT primitives 已存在不代表所有 System B fact/state/episode producer 都已经具备历史重放能力；缺口必须暴露，不得脑补。

---

## 9. 输入验证与失败语义

| 场景 | 规则 |
|---|---|
| subject 非 exactly-one | fail-fast |
| unknown universe | fail-fast |
| data key/必要 panel 缺失 | fail-fast |
| unknown score/filter field/op | fail-fast |
| 非法 target | 明确失败，不静默修复 |
| Strategy 缺正式 facts | fail-closed |
| PIT future leakage | strict 拒绝并报告 |
| research_assumptions | 仅 Experiment，可审计 |
| production side effects | 一律禁止 |

Task08 历史运行只读，不更新 canonical facts，不推进 state/episode，不创建 trade authorization。

## 11. 首次使用/Smoke

### 11.1 Factor

- 自动化：`data={prices, factors}` synthetic panel；

- holdings/state 跨日带入；

- 完整 target 序列进入 PortfolioEngine；
- 缺 facts 时准确 fail-closed。

首版 smoke 不要求 execution result 反向驱动次日 strategy state，但必须在 diagnostics/provenance 标记这一限制。

## 13. Definition of Done

Task08 完成必须同时满足：

- 一个统一 `back()` / 等价 CLI；三种 subject exactly-one；
- 正式 `data: Mapping[str, DataFrame] | None` 内存注入点，单元测试无需生产 DuckDB；
- `universe` 支持显式 tickers、`all_a`，`system_b_active_pools` 暂不启用并显式 fail-fast，未知字符串 fail-fast；
- Factor 用当前已有完整历史字段跑出可信真实结果，`m1_rank` 非硬依赖；
- Experiment 修改一个 score/filter/rank/weight/exit 参数即可 rerun；
- Experiment 无通用 DSL、无 Python `eval()`；
- Experiment/Strategy portfolio 复用现有 PortfolioEngine/execution；
- System B Strategy 使用 day-by-day formal driver + `strategy_result_to_target_weights()`；
- 不把多日 System B facts 一次性送入 `run_strategy_portfolio_backtest()`；
- 首版结果明确标记 `decision/target replay → execution simulation` 边界；
- execution 优先级可预测、冲突 fail-fast、resolved config 可审计；
- 所有历史运行只读；
- 每个 run 保存 request、data source、universe resolution、versions、resolved execution、metrics/artifacts；
- 至少完成一次真实单参数对比研究。

**不属于 DoD**：GUI、完整 Dry-Run、万能 DSL、批量参数搜索、全部 System B producer 历史化、execution-aware strategy closed-loop、产品 API 重构。

| D12 | Universe 仅有限命名 + 显式 tickers |

| D15 | subject 语义高于 preset 默认；显式 execution 冲突 fail-fast |
| D16 | 首版不宣称 execution-aware strategy closed-loop |

## 15. 已知限制

- `all_a` 的 loader 必须绑定真实现有表并测试；`system_b_active_pools` 待日级 PIT dynamic membership resolver 完成后再启用；
- 当前各 System B facts 的历史存储/PIT 完整度需要逐项实锤；
- 当前生产库未具备完整 `m1_rank / m1_score` 历史时，不为 smoke 伪造生产历史；
- System B day-by-day driver 首版按 formal decision/target state 维护 holdings；若以后需要 fills/rejections 反向构造次日实际 holdings，再评估 step/session；
- 原路线图“3–5 年”覆盖不足时应报告，不为凑年限制造未来泄漏或伪数据。

遇到缺口优先补最小 adapter/input assembly；只有证据证明底层能力确实不存在，才新增底层能力。

## 16. 给开发 Agent 的实现约束
