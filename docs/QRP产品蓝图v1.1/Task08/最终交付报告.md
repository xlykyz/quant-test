## 2. 交付目标

Task08 不建立新的回测系统，而是在 QRP 已有 Factor Research、PIT / historical data、PortfolioBacktestEngine、A 股 execution、formal Strategy 与 results/metrics 能力之上增加一个薄的统一编排层。

最终研究心智模型：

```text
Factor / Experiment / Strategy
            ↓
          back()
            ↓
        BackResult
```

核心目标已经实现：研究者可以修改一个指标、规则或参数，直接重新运行历史研究并获得可比较结果，而不再要求先补齐完整生产策略链路。

## 3. 最终实现范围

### 3.1 Unified `back()` Harness

统一入口：

```python
back(
    period,
    universe=None,
    *,
    factor=None,
    experiment=None,
    strategy=None,
    execution=None,
    output=None,
    data=None,
)
```

核心契约：

- `factor / experiment / strategy` 必须且只能提供一个；
- 所有调用归一化为 `BackRequest`；
- 返回统一 `BackResult`；
- 保存 request snapshot、config hash、git/version provenance、resolved execution、warnings 与 diagnostics。

### 3.2 内存数据注入

正式支持：

```python
data: Mapping[str, pd.DataFrame] | None
```

标准键包括：

- `prices`
- `factors`
- `facts`
- `universe_membership`

本地 Windows / CI / Notebook 可使用内存 DataFrame 完成验证；仅 `data is None` 时才进入真实数据库加载路径。

### 3.3 Factor Mode

Factor Mode 用于验证指标 / score 的历史信息价值，复用现有 cross-section research pipeline，输出 IC、Rank IC、forward return、quantile/group diagnostics 等结果。

最终方向契约已生效：

```text
higher_is_better → 原因子方向
lower_is_better  → Harness 对研究副本反向后进入 ResearchPipeline
```

调用方原始 DataFrame 不被修改；自动化测试已验证方向反转后 IC 符号对应反转。

### 3.4 Experiment Mode

首版支持：

- 单字段 score；
- 线性权重 score；
- 白名单 filter：`eq/ne/gt/ge/lt/le/in/not_in`；
- `rank.by == "score"`；
- `rank.order ∈ {"asc", "desc"}`；
- `top_n / weight_each`；
- `exit="when_not_selected"`。

明确禁止 Python `eval()`、万能 DSL、AST/parser。

任何未知字段、非法 rank 或不支持语义均 fail-fast，不做静默 fallback。

### 3.5 Strategy Mode

Formal Strategy 保持自身封装。

`system_b_portfolio` 使用 day-by-day formal driver：

```text
D 日 facts
  ↓
单日 StrategyInput
  ↓
上一日 StrategyHoldingState
  ↓
run_strategy_checked()
  ↓
StrategyPortfolioTarget
  ↓
strategy_result_to_target_weights()
  ↓
下一日 strategy state
```

完整 target-weight 序列最终进入 `PortfolioBacktestEngine` 进行 execution simulation。

只有明确列入 `VECTORIZED_STRATEGIES` 的策略才使用 vectorized runner；未分类 Strategy 一律 fail-fast，Harness 不猜执行模型。

## 5. Universe 最终契约

Task08 v1.1 正式支持：

1. 显式 `Sequence[str]` ticker list；
2. `"all_a"`。

保留但暂不启用：

```text
"system_b_active_pools"
```

原因：当前尚无可靠的 `trade_date`-level PIT membership resolver。跨 period 取成员并集会导致未来入池股票提前进入历史截面，因此该 preset 当前显式 fail-fast，等待真正日级动态 membership resolver 完成后再启用。

## 9. 已知边界

### 9.1 非 execution-aware fully closed-loop

Task08 v1.1 当前为：

```text
day-by-day decision / target replay
                ↓
complete target series
                ↓
batch execution simulation
```

fills、partial fills、rejected orders 与 execution drift 不反向改变下一日 formal strategy state。若未来研究证明有必要，再单独评估 PortfolioEngine step/session。

### 9.2 `system_b_active_pools` 暂未启用

等待真正日级 PIT membership resolver。

### 9.3 System B upstream facts 历史完整度仍受 producer 限制

Task08 不伪造 `comparison_score`、M1/M2/M3、authorization、severe abnormal、entry/exit facts。正式事实缺失时应准确报告缺口。

### 9.4 长周期全 A 研究需关注内存

当前 Harness 主要组织 pandas DataFrame。全 A、多年、多字段研究应合理控制 DuckDB projection 和内存占用。
